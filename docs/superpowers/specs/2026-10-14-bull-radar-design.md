# 飆股雷達設計規格

日期：2026-10-14
專案：`stock-research`
狀態：Design approved, implementation pending

## 1. 目標

在既有「選股研究工作台」新增第四個主頁「🚀 飆股雷達」，用固定規則從台灣上市／上櫃股票中找出符合「持續創高 + 不破前低」的強勢趨勢股。

核心原則：
- 找正在形成 Higher High（HH）與 Higher Low（HL）的股票。
- 以 20/60/240 日新高、均線排列、突破量能為主要技術條件。
- 月營收與其他基本面只作加分，不作必要條件，避免漏掉主升段股票。
- 每日批次計算後輸出結果，前端只讀取結果，不在手機端即時計算全市場。

## 2. 現有架構與限制

目前 `stock-research` 已有：
- 左側主導覽：研究工作台、七法與適用性、可行性與進度。
- 官方市場資料快照與每日 GitHub Actions 更新流程。
- 個股研究卡、公司目錄、行情／營收／估值／財報欄位。

目前不足：
- 沒有可供 HH/HL、MA20/MA60、20/60/240 日高點與量比計算使用的完整歷史價格序列。
- 現有 `market.json` 偏向最新快照，不適合直接做全市場波段掃描。

因此本功能需新增「歷史行情保存 + 雷達批次計算 + 前端呈現」三層。

## 3. 使用者流程

1. GitHub Actions 每日更新官方市場資料。
2. 更新流程追加歷史行情資料。
3. 雷達計算器掃描全市場。
4. 產生 `stock-research/data/radar.json`。
5. 前端「飆股雷達」頁直接讀取 `radar.json`。
6. 使用者可從雷達結果一鍵加入既有研究工作台。

## 4. 頁面結構

左側新增：
- `🚀 飆股雷達`

頁面上方 KPI：
- A 級候選數
- 今日新增 A 級數
- 創 240 日新高數
- 趨勢失效數

主要區域顯示 Top 10，欄位：
- 排名
- 股票代號／名稱
- 分數
- 趨勢結構
- 創高狀態
- 關鍵防守低點
- 量比
- 雷達狀態

狀態標籤：
- `A↑ 剛突破`
- `A↗ 主升段`
- `A↘ 拉回守穩`
- `A⚠ 接近失效`
- `❌ 趨勢失效`

視覺符號：
- 紅三角：創高／突破點
- 紅柱狀標記：確認後的 Higher Low／關鍵防守價

點選個股展開：

- 最近有效 HL 防守價
- 成交量與 20 日均量比較

- 「加入研究工作台」按鈕
- 「查看完整研究」按鈕

## 5. 固定 100 分模型

### 5.1 趨勢結構：45 分
- 240 日新高：20
- 60 日持續創高：10
- Higher High 成立：5
- 最近三個確認低點形成 Higher Low：10

### 5.2 均線與量價：25 分
- MA20 > MA60：10
- 收盤價 > MA20 > MA60：5
- 突破成交量 >= 20 日均量 1.5 倍：10

### 5.3 基本面輔助：20 分
- 月營收 YoY > 20%：10
- 月營收趨勢改善／連續成長：10

### 5.4 強度確認：10 分
- 距 60 日高點 <= 5%，或當日直接突破：5
- 相對強勢／近期價格動能：5

分級：
- A：80–100
- B：70–79
- C：60–69
- <60：不進主要雷達

規則補充：
- 基本面缺資料時不得直接判定不合格，只是不取得該項加分。
- 技術趨勢結構是主要核心。

## 6. HH / HL 判斷原則

第一版採固定 swing 規則，避免主觀判斷：
- swing high：某日高點高於前後各 N 個交易日高點。
- swing low：某日低點低於前後各 N 個交易日低點。
- 預設 N 由實作測試後固定在程式常數，不開放使用者調整。
- HH：最近兩個已確認 swing high，後者高於前者。
- HL：最近三個已確認 swing low 逐步抬高。
- 關鍵防守價：最近一個已確認 HL 的最低價。

避免使用尚未確認的最右側 swing 點，降低 repaint 問題。

## 7. A 級狀態分類

### A↑ 剛突破
- 當日或最近 3 個交易日創 60/240 日新高。
- 量價條件成立。

### A↗ 主升段
- HH + HL 仍成立。
- 價格維持 MA20 上方或回檔幅度有限。

### A↘ 拉回守穩
- 尚未跌破最近有效 HL。
- 拉回後仍維持 A 級。

### A⚠ 接近失效
- 現價距關鍵 HL 防守價過近。
- 預設警戒距離在實作測試後固定。

### ❌ 趨勢失效
- 收盤有效跌破最近確認 HL。
- 從主要 A 級排行移出，但保留於失效統計。

## 9. 新 A 級判斷

每日產生結果時，與前一份雷達結果比較：
- 昨日不是 A、今日成為 A => `newGradeA = true`
- 昨日已是 A、今日仍是 A => 不算新候選
- 曾跌出 A 後再次升回 A => 視為新 A，需保留日期資訊

這個定義需與每日「飆股雷達」提醒邏輯一致。

## 10. 與研究工作台整合

雷達頁不取代既有研究工作台。

責任分工：
- 飆股雷達：找「正在變強」的股票。
- 研究工作台：判斷公司品質、價格、催化、風險與研究證據。

雷達結果點「加入研究工作台」時：
- 使用既有公司目錄建立研究卡。
- 不直接把 A 級視為買進建議。
- 雷達分數只作為趨勢訊號，不改寫既有研究 gate 判斷。

## 11. 效能策略

採每日批次計算，而非瀏覽器即時計算全市場。

理由：
- 手機端載入更快。
- 每個裝置結果一致。
- 可在 GitHub Actions 中測試、重現與版本控制。
- 降低前端記憶體與 CPU 使用。

前端僅載入 `radar.json` 與單檔必要圖表資料。

## 12. 測試要求

至少包含：
- MA20 / MA60 計算測試
- 20/60/240 日新高測試
- volume ratio 測試
- HH / HL swing 判斷測試
- 跌破 HL 趨勢失效測試
- A/B/C 分級邊界測試
- 基本面缺資料時仍可依技術分數評級
- 昨日 B → 今日 A 的 `newGradeA` 測試
- 昨日 A → 今日 A 不重複標成新 A
- 雷達結果排序穩定性

## 14. 不在第一版範圍

第一版不做：
- 自訂權重
- 自訂 swing 參數
- 即時盤中掃描
- 自動下單
- AI 自動推薦買賣
- 籌碼資料作必要條件
- 複雜回測介面

後續可再新增進階設定與回測，但不阻塞第一版上線。

## 15. 成功條件

第一版完成需同時滿足：
- 工作台左側可進入「飆股雷達」。
- 每日自動產生全市場雷達結果。
- 可辨識 A/B/C 並排序 Top 10。
- 可看到紅三角創高與紅柱防守低點概念。
- 每檔 A 級可查看分數拆解。
- 可一鍵加入既有研究工作台。
- 手機版可正常操作。
- 不影響既有研究工作台資料與功能。
- 所有新增計算有自動化測試。
